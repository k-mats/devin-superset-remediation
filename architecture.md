# architecture.md

## High-Level Flow

```
GitHub issue/event
    ↓
orchestrator
    ↓
Devin API
    ↓
pull request
    ↓
verification/reporting
```

## Components

### GitHub Issue/Event Source

- GitHub webhook or event polling mechanism
- Triggers when issues are created or updated
- TBD - webhook vs polling decision

### Orchestrator

- Receives and processes GitHub events
- Evaluates whether issues should be automated
- Manages Devin API sessions
- Tracks status and results
- **Implementation**: TypeScript/Node.js with Fastify framework

### Devin API

- External API for creating and managing Devin sessions
- Provides session status and results
- TBD - specific API endpoints and authentication

### Pull Request

- Generated by Devin in the target repository
- Represents the remediation work
- May require human review before merging

### Verification/Reporting

- Confirms pull request was created
- Reports status back to the team
- TBD - reporting mechanism (GitHub comment, dashboard, etc.)

## Persistence

The orchestrator persists:

- GitHub event metadata
- Devin session IDs and status
- Mapping between issues and sessions
- **Technology**: SQLite with Drizzle ORM and better-sqlite3 driver

## Architectural Constraints

- Must be idempotent - duplicate events should not create duplicate Devin sessions
- Must handle failures gracefully between external calls and persistence
- Must not modify the Apache Superset fork directly (only via Devin-generated PRs)
- Must preserve evidence for the take-home evaluation

## Technology Choices

The following have been selected:

- **Implementation language**: TypeScript 6.0.3
- **Runtime**: Node.js 24 LTS (24.21.0)
- **Web framework**: Fastify 5
- **Database technology**: SQLite with Drizzle ORM and better-sqlite3
- **Package manager**: pnpm 12.4.2
- **Testing framework**: Vitest 5
- **Linting**: ESLint 10 with typescript-eslint flat config
- **Formatting**: Prettier
- **Deployment method**: Docker with Node 24.21.0 Alpine base image
